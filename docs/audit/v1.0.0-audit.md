# ResearchOS v1.0.0 — Comprehensive Architecture & Implementation Audit

**Audit Date**: 2026-08-31  
**Baseline Release**: `v1.0.0` (`67a43db`)  
**Target Milestone**: `v1.1 — Real System Hardening`  
**Auditor**: Senior Staff Engineer & Solution Architect

---

## 1. Executive Summary

ResearchOS is an architecturally sophisticated product with a clear value proposition: a **10-archetype Knowledge DAG** connecting literature, empirical experiments, and claims into a verified provenance chain.

However, a rigorous inspection of the `v1.0.0` codebase confirms the primary architectural risks:
1. **Silent Client Fallback**: `src/services/api/client.ts` catches backend network errors and silently redirects calls to an in-memory/`localStorage` mock router (`handleInternalRoute`), masking connectivity and schema mismatches.
2. **Leftover Firebase Dependency**: `package.json` and `src/services/firebase/firebase.ts` still import and initialize Firebase Firestore.
3. **Hardcoded Docker Secrets**: `docker-compose.yml` contains concrete passwords and JWT secret keys in the default configuration.
4. **Mocked AI Generation**: While the `AIProvider` gateway abstraction is clean, the default provider returns deterministic mock citations rather than executing real grounded retrieval pipelines.

## 3. Findings Categorization

### 🔴 P0 Critical (Security & Data Integrity)
- **[FINDING-01] Silent Mock Fallback in Frontend Client**:
  - *Location*: `src/services/api/client.ts:944-948`
  - *Current Behavior*: If FastAPI is down or returns network error, `client.ts` catches it and runs `handleInternalRoute` which saves/loads from `localStorage`.
  - *Expected Behavior*: In dev/prod, a network failure must throw an authoritative error and display a clear connection error state in the UI. Mocks must only execute in explicit test fixtures.
  - *Recommendation*: Remove `handleInternalRoute` from normal runtime; fail fast when backend is unavailable.
- **[FINDING-02] Plaintext Secrets in Docker Compose**:
  - *Location*: `docker-compose.yml:25-27`
  - *Current Behavior*: `JWT_SECRET_KEY` and `POSTGRES_PASSWORD` have concrete fallback secrets in repo.
  - *Expected Behavior*: Fallback values must be removed or strictly sourced from untracked `.env`.
  - *Recommendation*: Update `docker-compose.yml` to strictly require `.env` or use non-critical placeholder variables; ensure `.env` is ignored.

### 🔴 P1 High (Architecture Cleanliness & Real RAG)
- **[FINDING-03] Leftover Firebase Dependency**:
  - *Location*: `package.json`, `src/services/firebase/firebase.ts`, `src/services/api/client.ts:12-13`
  - *Current Behavior*: Firestore client is initialized and imported in `client.ts`.
  - *Expected Behavior*: PostgreSQL is the single source of truth.
  - *Recommendation*: Remove Firebase SDK and unused Firestore files.
- **[FINDING-04] AI Grounding & Provider Invocation**:
  - *Location*: `backend/app/ai/gateway/provider.py`
  - *Current Behavior*: `GeminiProvider` checks `GEMINI_API_KEY`, but falls back to `MockLocalProvider`.
  - *Expected Behavior*: Real HTTP integration with Google GenAI / Gemini 1.5 Pro when key is supplied, with clear validation of retrieved graph citations.
- **[FINDING-05] Server-State Separation in Frontend**:
  - *Location*: `src/store/useResearchStore.ts`
  - *Current Behavior*: Zustand stores all 10 entity arrays in memory and manages sync manually.
  - *Expected Behavior*: Separate client UI state (modals, selection, filters) from server entity synchronization.

### 🟠 P2 Medium (Testing & Quality)
- **[FINDING-06] Negative Authorization Tests**:
  - *Current Behavior*: Tests verify happy path workspace access.
  - *Expected Behavior*: Explicit negative test asserting User B cannot read or mutate Workspace A's research graph even with knowledge of UUIDs.

## 4. Remediation Plan & Execution Sequence

1. **Step 1 (Security)**: Clean `docker-compose.yml` secrets, verify `.env` loading, rotate development secrets.
2. **Step 2 (Data Integrity)**: Remove `handleInternalRoute` and `localStorage` mock database from `client.ts`.
3. **Step 3 (Dependency Cleanup)**: Uninstall `firebase` from `package.json` and remove `src/services/firebase/`.
4. **Step 4 (AI Hardening)**: Integrate real `google-genai` / `aiohttp` call in `GeminiProvider` when `GEMINI_API_KEY` is provided.
5. **Step 5 (Verification & Tests)**: Add negative authorization pytest tests for cross-tenant IDOR defense.
