# ResearchOS v1.1 — Hardening Implementation Plan

**Objective**: Convert the existing v1.0.0 prototype into a hardened, authoritative, secure, and genuinely persisted ResearchOS core.

---

## 1. Work Package 1: Security & Credential Hygiene (P0)
- [ ] Remove hardcoded default passwords and JWT secrets from `docker-compose.yml`.
- [ ] Verify `.env` is in `.gitignore` and `.env.example` contains only non-sensitive templates.
- [ ] Confirm and document secret rotation requirements.

## 2. Work Package 2: Elimination of Silent Mock Backend (P0)
- [ ] Refactor `src/services/api/client.ts` to remove the 800-line `handleInternalRoute` mock database.
- [ ] Ensure any network failure triggers a clear, user-facing connection/offline alert instead of silently fabricating or reading `localStorage` state.
- [ ] Keep mock data strictly within test suites (`src/test/`).

## 3. Work Package 3: Removal of Secondary Persistence (Firebase) (P1)
- [ ] Remove `firebase` package from `package.json`.
- [ ] Delete `src/services/firebase/` and any unused Firestore helpers.
- [ ] Ensure PostgreSQL via FastAPI `/api/v1` is the single source of truth.

## 4. Work Package 4: Real Grounded AI Gateway & Citations (P1)
- [ ] Update `backend/app/ai/gateway/provider.py` with real HTTP calls to Gemini 1.5 Pro when `GEMINI_API_KEY` is present.
- [ ] Log AI prompt execution, token usage, and graph citation mappings.

## 5. Work Package 5: Multi-Tenant Authorization & Negative Tests (P2)
- [ ] Add negative pytest suite verifying that User B receives `403 Forbidden` / `404 Not Found` when trying to access Workspace A entities.
- [ ] Verify complete backward provenance trace from Decision `D-001` back to Research Question `Q-001` with 100% database persistence.
